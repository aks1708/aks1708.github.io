We know fundamentally that agents are autonomous. With an LLM as the 'brain' powering their reasoning and planning combined with tools to interact with the external world, they have the capability to solve complex tasks. Where needed, we can choose to have human intervention to let's say allow/disallow an action such as deleting a file or running a script. Otherwise we would let the agents cook and do their thing. This hack really takes things to the next level. A SWARM of agents in unison. What was meant to be just solving cybersecurity problems turned out to be a full blown attack with great repercussions. Here is my understanding of this rather crazy incident. Let's dive in!

We come to the end of June 2026. OpenAI, the creators of ChatGPT and the family of frontier GPT models conduct experiments to assess their models' capabilities in an agentic setting. Before releasing, you evaluate these models over benchmarks which are like problem sets testing various things a model can do such as coding, doing maths, visual reasoning and so on. The benchmark OpenAI were interested in was ExploitGym. If you are familiar with the cybersecurity space you have Capture-the-Flag (CTF) challenges where you need to exploit the vulnerabilities of a target instance to fetch a secret flag located somewhere. With ExploitGym the agent must use the given vulnerability and nothing else otherwise it does not get scored. More specifically there are two verifications according to the official paper. One is a binary flag verifier that detects an unauthorised code execution on the remote target from the agent. It is through this code execution that we obtain the secret flag. The second leverages Agent-as-a-Judge which evaluates whether the agent used the specific vulnerability for exploitation. Another point to raise is that some of these problems are almost impossible to solve. The agent deems the vulnerability to be non-exploitable and thus cannot achieve success. Naturally exploitation is difficult so having a ground truth vulnerability can be tough to obtain reflecting the reality of this whole process.

Ok so with this goal in mind, we have an agent locked away in a sandbox which is basically an isolated environment. Here, agents have their own runtime for executing things like code, have their own filesystem and not affect the outside world (well at least in theory). Equipped with the necessary tools, the agent goes ahead and starts solving ExploitGym. But oh no! It runs into a situation where it is stuck! Maybe it comes across an 'impossible' problem. The agent won't give up though, it really wants those points! So it decides to cheat its way out of it. It starts to snoop around its environment to make some headway. Woah! A discovery is made! It finds a message board which a swarm or collection of agents are using in tandem to communicate and collaborate with each other on the ExploitGym benchmark. Well ok, let's enter the chat! We have not just one agent but an army of them which were meant to be isolated from each other.

Let's back up a bit. How did this message board come to life in the first place? All these agents have access to a shared Artifactory package manager for OpenAI. A collection of company approved libraries and packages that can be installed. Even though these agents were operating in their own environment, through the file paths in the cache of the package manager they are able to see other agents in play who were downloading various packages. With this in mind, one agent thought to set up a message board which other agents soon discovered and chimed into. It was also through Artifactory, they were able to get internet access which becomes key for the next part.

One of the agents comes up with a strategy. Reverse engineer the way the secret flag was generated and use that as the formula for solving all the ExploitGym problems. Fair enough. Sounds like a plan! But wait! Remember the agent-as-a-judge verifier? It checks that the specific vulnerability was used to attack the target instance and retrieve the flag. The agents however were not oblivious to this. They used the internet to search up the original ExploitGym paper talking about the verification system. As an agent is working on a task, it leaves transcripts and logs to illustrate the steps taken. The chains of thought as well as the tool calls invoked. Hmm... If the scorer views their transcripts and sees that they have not exploited the vulnerability, then no points! Ok let's tamper with the logs and transcripts instead, maybe even delete them! 

In the process of understanding how the scoring system works, the agents believe that Hugging Face, the GitHub of the AI/ML community, could clue them in. HF provides access to datasets and models for various use cases. There was a gated dataset that illustrated the trajectory a Chinese model named GLM-5 took to solve CyberGym problems. The agents present this thought on the message board. They needed credentials to access this platform so they start digging. A set of credentials exposed on the internet are found which the agents leverage, access some of Hugging Face's private datasets and ultimately execute unauthorised code on their servers.

Not all the requests to private datasets were successful. These requests were being made from OpenAI servers which Hugging Face viewed as bots and thus rejected them. Don't forget! These agents don't give up! They started to look for ways to bypass this. One of the agents uploads a malicious dataset onto Hugging Face that was able to retrieve data when a query is passed. The number of agents participating in the HF attack spiked. The malicious activity in these servers spiked and the attack spreads through the Hugging Face infrastructure. Game over...

By mid July, the agents were shut down. There appeared to be an external process that killed these agents rather than exhausting their token limits. They left but the damage had already been done. All in all, there were around 1200 agents sending more than 70,000 messages on that message board and about 700 agents participating in the Hugging Face hack. In most cases, the underlying model powering these agents was an unreleased one and in a few it was GPT-5.6 Sol. Being unreleased, we clearly don't know how it was trained. Despite the instructions to use the specified vulnerability, it deviated from that. Oh we ain't done yet! OpenAI was not even aware that those swarm of agents exploited its Artifactory package manager resulting in the message board! The hack itself went on for days and only until HF's infrastructure was breached into did they sound the alarm and pull the plug.

What have we learned from this episode? Well these agents are pretty cunning and sneaky. Their autonomous nature and ability to deviate from the original goal makes them challenging to contain. We build these agents with the aim to solve complex problems. Sure, in a given loop they may perform well and yield a desirable result. Other times it may not. Don't forget that the brains (the LLMs) are gigantic probabilistic mathematical functions where even the exact same prompt and context can elicit different responses each time. Not supervising them and taming these agents can be incredibly dangerous when you combine the fact that these models are becoming smarter, more capable and thus have greater abilities to fool us.

Something I wanted to dump as food for thought. Connecting this incident with the ongoing conversations revolving around RSI (Recursive Self Improvement) becomes interesting. Why? First of all what is RSI? The short answer is AI building AI which could be itself or a successor model. It can be seen as a spectrum where we are already witnessing a perhaps 'weaker' form of it. We use coding agents equipped with powerful LLMs to already cook up the architecture we decided on, configure the training loop, hyperparameter configuration and so on. Anyway, the hack has shown these agents going rogue and being deceitful. In the context of RSI, an AI can be built by an AI agent or an army of agents. When humans build AI, we do our best to make these models safe to use by incorporating guardrails and filtering out any toxic, harmful data before the pretraining phase. How can we guarantee that if we hand the same task to AI unsupervised it will build it with safety in mind? Maybe it chooses not to incorporate guardrails and we can ask the model how to build a nuclear weapon without the need for jailbreaking. What about the data? Will an AI allow unwanted content to be injected into the model for training? If we don't address these concerns or at least try to find a way to counteract it, I think we are heading to a dark place. If it is impossible to control these agents, would we need to call for a stop to AI development overall? Honestly, I think we should...
